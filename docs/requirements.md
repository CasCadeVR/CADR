# Функциональные требования CADR Portal

## 1. Аутентификация и профиль
- Регистрация, вход (cookie-автологин), выход.
- Профиль (`/account/profile`): данные пользователя + переключатель-табы
  организаций + его ADR в каждой из них.
- Профиль другого участника (`/organization/{orgId}/users/{userId}/profile`):
  данные + роль в организации + его ADR.
- Проверка: войти, открыть профиль, переключить табы организации;
  кликнуть автора на карточке ADR.

## 2. Организации и дашборд
- После входа — дашборд первой организации; если есть приглашения — их алерт.
- Дашборд организации: последние 10 ADR (по дате изменения), блок «мои ADR»,
  кнопки «Создать ADR» (Architect/Admin) и «Все ADR организации».
- Топбар: выпадающий список организаций пользователя → дашборд выбранной.

## 3. ADR-контент (проводник)
- Список `/organization/{orgId}/adrs`: папки + ADR одной таблицей
  (как файловый проводник), хлебные крошки, навигация по папкам.
- Фильтры по статусу (каждый статус — таб, счётчики, ленивая загрузка).
- Создание/переименование/удаление папок (удаление каскадное, с предупреждением).
- Drag-and-drop ADR и папок в папки и на хлебные крошки (движение вверх).
- Создание ADR в конкретную папку (`?folder=`), удаление ADR (с предупреждением).
- Проверка: зайти в «Все ADR организации», создать папку, перетащить ADR,
  удалить папку с содержимым.

## 4. ADR: создание и редактирование
- Форма: название, выбор шаблона (секции шаблона предзаполняются, при
  изменённых секциях — подтверждение замены), секции с up/down/удалением,
  подсказки (hint/placeholder) из шаблона.
- Создание: статус Proposed (Draft создаётся сервисом по внутренним правилам),
  номер присваивается автоматически.
- Проверка: создать ADR по шаблону, убедиться в подсказках, отредактировать.

## 5. ADR: жизненный цикл
- Страница ADR: секции, голоса (лайк/дислайк, отзыв повторным кликом,
  автоодобрение по порогу организации), комментарии (создание/удаление своих),
  метаданные, связи, экспорт.
- Смена статуса: дропдаун допустимых переходов (матрица ролей — см.
  users-and-organizations.md).
- Связи: 3 типа (RelatedTo / Supersedes / DeprecatedBy), выбор типа → модалка
  с поиском по названию/номеру, исключены сам ADR и уже связанные; удаление связи.
- Проверка: проголосовать до порога (автоодобрение), сменить статус админом,
  создать и удалить связь.

## 6. Экспорт
- Один ADR → `ADR-{номер}.md`; все одобренные организации → один документ.
- Проверка: кнопки «Экспортировать в MD» на странице ADR и на вкладке
  «Одобренные» списка.

## 7. Шаблоны
- Настройки организации (`/organization/{orgId}/adr-settings`): порог
  автоодобрения + таблица шаблонов (встроенные — только просмотр).
- Создание/редактирование/удаление собственных шаблонов (секции: заголовок,
  подсказка, placeholder).
- Проверка: создать шаблон, создать ADR по нему, удалить шаблон.

## 8. Приглашения
- Admin приглашает пользователя по логину с ролью; приглашение видно
  адресату на дашборде.
