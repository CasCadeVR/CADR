# Пользователи, организации и роли

## Роли
Роль назначается в рамках конкретной организации (UserOrganization.Role):

| Роль | Возможности |
|---|---|
| **User** | Просмотр папок и ADR, комментарии, голосование (не за своё), просмотр профилей участников, свой профиль с ADR по организациям |
| **Architect** | Всё из User + создание/редактирование/удаление ADR и папок, перенос ADR (drag-and-drop), создание связей, перевод Draft → Proposed, NeedsRevision → Proposed |
| **Admin** | Всё из Architect + управление настройками организации, приглашения/роли участников, перевод статусов (Proposed → Approved/Rejected и т.п.), удаление ADR/папок/шаблонов |

Глобальных ролей нет: один и тот же пользователь может быть Admin в одной
организации и User в другой. Проверки выполняются на сервере
(`AccessService` / `ThrowIfNotMemberAsync`, `ThrowIfNotAdminOrArchitectureAsync`);
UI лишь скрывает недоступные кнопки (например, порог видимости «Создать ADR»
по `RequestingUserRole` в ответе организации).

## Матрица переходов статусов ADR
(реализация — `AdrManager.IsTransitionAllowed`; зеркалируется на клиенте в
`AdrsHelper.GetAllowedTargetStatuses`)

| Из \ В | Proposed | Approved | Rejected | NeedsRevision | Deprecated |
|---|---|---|---|---|---|
| Draft | Architect, Admin | — | — | — | — |
| Proposed | — | Admin (или голосами) | Admin | — | — |
| Approved | — | — | — | Admin | Admin или автор |
| NeedsRevision | Architect, Admin | Admin | — | — | Admin или автор |
| Rejected | Admin | — | — | — | — |

## Жизненный цикл членства
1. Регистрация → пользователь без организаций.
2. Создание организации (пользователь становится её Admin) **или** приём
   приглашения (Invite: Pending → Accepted; роль из приглашения).
3. Приглашения видны на дашборде сразу после входа.
4. Вышедший/удалённый участник теряет доступ ко всем страницам организации
   (403/404 → редирект на дашборд приглашений).
